# 손 점검 체크리스트 (사이클 계획 1·2단계 끝, 11/22)

자동 테스트로 볼 수 없는 것(결제사 화면, 실제 기기 알림, 브라우저 뒤로 가기, 실제 간편 로그인)과 역할 한 바퀴를 사람이 직접 본다. 회귀 시나리오(`docs/test-scenarios.md`)의 🖐 줄과 같다. 결과는 nnoinn이 Claude에게 알려 주면 시나리오 표에 날짜와 함께 적는다.

- 장소: `https://toori.kr`(개발 DB, 포트원 테스트 결제). 처음 열 때 팀 접속 코드를 넣는다
- 계정: 각자의 진짜 카카오·구글 계정(시드 계정은 로그인할 수 없다). 원장님 샵이 없으면 `npm run scenario -- owner-shop approved`로 만든다
- 테스트 결제는 실제 돈이 나가지 않는 포트원 테스트 모드다. 결제 뒤 바로 취소해서 환불까지 본다

| # | 시나리오 | 할 일 | 확인할 것 | 결과 |
| --- | --- | --- | --- | --- |
| 1 | AUTH-07 간편 로그인 | [첫 화면](https://toori.kr/)에서 고객으로, 다시 원장님으로 카카오·구글 로그인 | 각각 들어가지고, 로그인 버튼의 "최근 로그인" 표시가 맞다 | |
| 2 | AUTH-08 로그아웃 | 로그인한 채로 [내 정보](https://toori.kr/me)에서 로그아웃 → 브라우저 뒤로 가기 | 첫 화면이 새로 열리고, 뒤로 가도 로그인한 화면이 다시 보이지 않는다 | |
| 3 | FLOW-06 실제 결제·환불 | [고객 홈](https://toori.kr/home)에서 매물을 골라 [예약하기] → 결제창에서 테스트 결제 → [내 예약](https://toori.kr/reservations)에서 취소 | 결제 완료 화면, 예약 확정 알림, 위약금 구간대로 환불 금액, 포트원 콘솔의 취소 내역 | |
| 4 | FLOW-07 웹 푸시(PC·폰) | PC와 폰 각각 [내 정보](https://toori.kr/me)의 알림 설정에서 푸시 알림 켜기 → 다른 계정으로 내 샵 매물 예약 | 기기에 알림이 뜨고, 누르면 그 예약 화면이 열린다(원장님·고객 모두) | |
| 5 | 역할 한 바퀴 | 원장님으로 매물 등록 → 고객으로 예약·결제 → 원장님 [대시보드](https://toori.kr/owner)에서 방문 처리 → 운영자 [입구](https://toori.kr/admin/login)로 들어가 그 예약·샵 정산·기록 보기 | 세 역할 화면의 상태·금액·알림이 서로 맞고, 이상한 점이 없다 | |

이상한 점을 찾으면 화면 주소와 사진을 Claude에게 주면 담당자에게 Issue로 전한다.
