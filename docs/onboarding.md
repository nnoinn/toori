# 팀원 매뉴얼

팀원이 Claude Code로 투리를 개발하면서 알아야 할 것을 모은 문서다. 직접 읽어도 되고, Claude에게 "매뉴얼 보고 알려줘"라고 물어도 된다. Claude는 팀원이 사용법·Git·환경 설정·오류를 물으면 이 문서를 기준으로 답한다.

## 0. 문서 지도

| 문서 | 내용 | 언제 보나 |
| --- | --- | --- |

## 1. 한눈에 보는 작업 방식

```text
main 받기 → 내 브랜치 만들기 → 기능 하나 만들 때마다 커밋
→ (하루 끝, 또는 배포 주소로 확인하고 싶을 때) 푸시
→ 영역 하나가 끝나면 PR → 현동훈 리뷰
→ 반려되면 같은 브랜치에서 고쳐서 다시 푸시 → 현동훈이 main에 머지
```

- 모든 변경은 PR로 들어간다. main에 직접 올리지 않는다. 머지는 현동훈(nnoinn)만 한다.
- 각자 담당 폴더 안에서만 작업한다(CLAUDE.md 팀 표). 다른 사람 폴더가 필요하면 Issue로 요청한다.
- 기능은 ID로 부른다. "C-202 만들어줘"라고 하면 Claude가 명세를 찾아 만든다.

### 사람이 하는 일과 Claude가 하는 일

| 사람 (팀원) | Claude |
| --- | --- |
| 무엇을 만들지 말한다 ("C-202 만들자") | 명세·기술 가이드·코드 규칙을 찾아 읽고 계획을 세운다 |
| 계획을 보고 의견을 주고 승인한다 | 승인된 계획대로 만들고, 쉬운 말로 설명한다 |
| 화면을 직접 눌러 보고 이상한 점을 말한다 | 고치고, 자동 검사를 돌리고, 커밋·푸시·PR까지 진행한다 |
| 설명을 듣고 이해한다 (모르면 묻는다) | 브랜치·충돌·리뷰 반영 같은 Git 작업을 처리한다 |
| 막히면 단톡에 공유한다 | 다른 담당자 기능이 필요하면 Issue 내용을 정리해 준다 |

### 세션을 열면 Claude가 먼저 알려주는 것

Claude Code에서 레포 폴더(10/12 전에 클론했다면 `jupjup`, 그 뒤면 `toori`)로 세션을 열면, 첫 메시지에 답하기 전에 Claude가 짧은 **세션 시작 브리핑**을 먼저 해 준다. 아무 말이나 보내면 된다(예: "작업 시작").

- main을 최신으로 자동 업데이트 ("main 받아줘"라고 하지 않아도 된다)
- 지난번 이후 main에 머지된 변경과 **새 팀 공지**(현동훈이 남긴 할 일 포함)
- 바뀐 규칙·문서 (Claude가 다시 읽고 무엇이 바뀌었는지 알려준다)
- 내 PR 상태 (특히 **수정 요청**을 받았으면 그것부터 하자고 제안한다)와 나에게 배정된 Issue
- 지금 브랜치 상태와 오늘 할 다음 단계

한 세션을 오래 쓰는 중에도 "작업 시작" 또는 "새 작업"이라고 하면 다시 최신화하고 브리핑해 준다.

## 2. 처음 세팅 (한 번만)

### 2-1. 프로그램 설치

**Windows:** 시작 메뉴에서 "터미널"을 열고 한 줄씩 실행한 뒤, 터미널을 닫고 새로 연다.

```powershell
winget install --id Git.Git -e
winget install --id GitHub.cli -e
```

**Mac:** 터미널에서 Homebrew를 설치한다(끝에 나오는 "Next steps" 명령을 꼭 실행). 그다음 `brew install git gh`를 실행한다.

**Node.js(둘 다):** [nodejs.org/dist/latest-v24.x](https://nodejs.org/dist/latest-v24.x/)에서 **24 버전** 설치 파일을 받아 설치한다. Windows는 `node-v24.…-x64.msi`, Mac은 `node-v24.….pkg`다. 10월 말부터 "LTS" 최신이 26으로 바뀌므로 LTS 버튼 대신 24를 직접 고른다

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치 확인: `git --version`, `node -v`, `gh --version` 세 개가 버전을 출력하면 된다. **Node는 24 버전**(`v24.`로 시작)이어야 한다. 다른 버전이면 위 링크에서 24를 다시 설치한다(GitHub 자동 검사와 Vercel도 24를 쓴다). 설치 후 **Claude 앱을 완전히 종료했다가 다시 켠다**(Windows는 작업 표시줄 트레이 아이콘에서 종료, Mac은 `Cmd`+`Q`).

### 2-2. GitHub 로그인 연결

터미널에서 `gh auth login`을 실행하고 GitHub.com → HTTPS → Yes → Login with a web browser를 고른다. 화면의 코드를 브라우저에 입력하고 Authorize. `gh auth status`로 확인한다.

### 2-3. Git 작성자 설정 (Claude에게)

```text
gh로 내 GitHub 계정을 확인해서 git 전역 설정의 이름은 "영문 이름",
이메일은 내 GitHub noreply 주소로 설정해줘. 끝나면 설정된 값을 보여줘.
```

### 2-4. 레포 받기와 작업 폴더

1. 작업 폴더를 만들고 Claude Code에서 그 폴더로 세션을 연다.
2. "GitHub의 nnoinn/toori 레포를 이 폴더에 클론해줘."
3. **세션의 프로젝트 폴더는 레포 최상위 폴더(README.md와 .git이 있는 곳)여야 한다.** 확인: "지금 세션 폴더가 toori 레포의 최상위 폴더인지 확인해줘."

### 2-5. 환경변수 파일(.env.local) 받기

- `.env.local`은 DB 비밀번호와 비밀 키가 들어 있어 GitHub에 올라가지 않는다. **현동훈이 팀원 4명만 있는 단톡방에 올린다** (개발용 키만, 뼈대 완성 후).
- 받으면 바로 레포 최상위 폴더에 `.env.local`이라는 이름으로 저장한다. Claude에게 "레포 최상위 폴더에 빈 .env.local 파일을 만들고 메모장(Mac은 텍스트 편집기)으로 열어줘"라고 한 뒤, 열린 파일에 단톡방 내용을 붙여넣고 저장한다. 키 값은 Claude 채팅에 붙이지 않는다. 어떤 변수가 있는지는 `.env.example`에서 볼 수 있다.
- **파일 이름이 틀리기 쉽다.** Windows 메모장으로 직접 만들면 `.env.local.txt`가 될 수 있고, Mac Finder에서는 점(.)으로 시작하는 파일이 숨겨진다(`Cmd`+`Shift`+`.`으로 보기). 저장한 뒤 2-7 점검으로 이름이 정확한지 확인한다.
- 세 명 모두 저장했다고 답하면 현동훈이 단톡방의 그 메시지를 지운다. 받은 키를 다른 곳(다른 단톡방, 노션, Issue·PR, 스크린샷)에 다시 붙이지 않는다.
- 잃어버리면 현동훈에게 다시 요청한다. 팀원이 바뀌거나 단톡방에 다른 사람이 들어오면 현동훈이 키를 새로 발급한다.

### 2-6. Windows와 Mac이 섞여 있어도 괜찮은 이유

- 레포, 명령, 검사는 같다. 명령은 Claude에게 시키면 내 컴퓨터에 맞게 실행한다
- 줄바꿈(Windows CRLF, Mac LF)은 레포 설정(`.gitattributes`)이 LF로 맞춘다. `npm run format`이 나머지를 정리한다
- **파일 이름 대소문자만 조심한다.** Windows와 Mac은 `Button.tsx`와 `button.tsx`를 같은 파일로 보지만, GitHub 자동 검사와 Vercel(리눅스)은 다른 파일로 본다. import 경로의 대소문자가 실제 파일과 다르면 내 컴퓨터에서는 되고 PR 검사에서만 실패한다. 파일 이름의 대소문자를 바꿀 때는 Claude에게 "git mv로 이름 바꿔줘"라고 한다
- 단축키는 Windows `Ctrl` = Mac `Cmd`. 문서와 코드의 경로는 `/`로 쓴다

### 2-7. 점검

```text
온보딩 점검해줘. git·node·gh 버전, gh 로그인 계정, git 작성자 이름·이메일,
toori 레포 연결 상태(주소가 nnoinn/toori인지), .env.local이 있는지(값은 출력하지 말고)를 표로 보여줘.
```

### 2-8. 처음 실행해 보기

Claude에게 "처음 실행해줘"라고 하면 아래를 대신 해 준다.

1. `npm install`: 필요한 패키지를 받는다(몇 분 걸린다)
2. `npm run dev`: 개발 서버를 켠다
3. 브라우저에서 `http://localhost:3000`(고객 홈), `/owner`(원장님), `/admin`(운영자)이 열리면 성공이다

자주 쓰는 명령은 Claude가 알아서 실행한다. 직접 알 필요는 없지만 이름만 알아 두면 좋다.

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 켜기 (코드를 고치면 바로 반영) |
| `npm run lint` · `npm run typecheck` · `npm test` · `npm run build` | 자동 검사. PR을 올리면 GitHub에서도 똑같이 돈다 |
| `npm run format` | 코드 모양을 팀 규칙대로 정리 |

## 3. Git·GitHub 기본 개념

코드가 머무는 곳은 세 군데다: ① 내 PC의 작업 폴더 ② 내 PC의 Git 기록(커밋) ③ GitHub(팀 전체가 보는 곳).

| 용어 | 뜻 |
| --- | --- |
| 커밋 | ①의 변경을 ②에 저장 지점으로 기록. 내 PC에만 있다 |
| 푸시 | ②의 아직 안 올린 커밋을 전부 ③의 내 브랜치로 올림 |
| 풀(pull) | ③의 최신 내용을 내 PC로 받기 |
| 브랜치 | 커밋이 쌓이는 줄기. main은 정본, 각자 자기 브랜치에서 작업 |
| PR | "내 브랜치를 main에 합쳐 주세요"라는 요청 페이지. 리뷰와 자동 검사가 여기서 일어난다 |
| 머지 | PR을 main에 합치기. 현동훈만 한다(Squash merge: 커밋 여러 개가 main에 1개로 합쳐짐) |
| 충돌 | 두 사람이 같은 줄을 다르게 고쳐서 자동으로 합칠 수 없는 상태. 작성자가 자기 브랜치에서 푼다 |
| `.env` 파일 | 비밀 키 파일. GitHub에 올리지 않는다 |

## 4. Claude Code 사용법

### 권한 모드 (전송 버튼 옆, `Ctrl`/`Cmd`+`Shift`+`M`)

| 모드 | 하는 일 | 우리 팀 사용법 |
| --- | --- | --- |
| Manual | 파일 수정·명령 실행마다 물어본다 | 익숙해지기 전 |
| Plan | 코드는 고치지 않고 계획만 세운다 | 새 기능을 시작할 때 |
| Accept edits | 파일 수정은 자동, 그 외 명령은 물어본다 | 계획 승인 후 구현할 때 기본값 |
| Auto | 위험한 동작만 검사기가 걸러낸다 | 익숙해진 뒤 선택 |
| Bypass permissions | 거의 모든 승인을 건너뛴다 | **사용 금지** |

### 자주 쓰는 기능

| 기능 | 방법 |
| --- | --- |
| 중단·방향 수정 | `Esc` 또는 정지 버튼. 실행 중에 정정 메시지를 보내도 된다 |
| 파일 참고시키기 | 입력창에 `@` + 파일명 (예: `@docs/feature-spec.md`) |
| 변경 확인 | `+12 -1` 같은 표시 클릭, 또는 `Ctrl`/`Cmd`+`Shift`+`D`. 줄을 클릭하면 수정 요청 코멘트를 남길 수 있다 |
| 코드 리뷰 | diff 화면 오른쪽 위 **Review code** (PR 올리기 전에) |
| 곁질문 | `Ctrl`/`Cmd`+`;` 또는 `/btw` |
| 터미널 | `Ctrl`+`` ` `` (Mac도 Ctrl) |
| 사용량 확인 | 모델 선택 옆 원형 표시 |

### 세션

- 한 세션을 계속 이어서 써도 된다. 응답이 이상해지거나 느려지거나 사용량 경고가 뜨면 새 세션을 연다.
- 팀 규칙(CLAUDE.md)이나 문서가 바뀌면, Claude가 pull할 때 알아서 다시 읽고 무엇이 바뀌었는지 알려준다.

### 사용량 아끼는 습관

- "알아서 잘"보다 기능 ID, 폴더, 완료 조건을 구체적으로 말한다.
- 같은 실수를 반복하면 계속 조르지 말고, 무엇이 틀렸는지 알려준 뒤 새 세션에서 다시 시킨다.

## 5. 매일 작업 흐름 (그대로 복사해서 쓰는 문장)

| 단계 | 보낼 문장 |
| --- | --- |
| ① 시작 | "작업 시작. 오늘은 C-202 할 거야. 브랜치 만들어줘." (Claude가 최신화·브리핑 후 브랜치를 만든다) |
| ② 계획 (Plan 모드) | "C-202를 만들려고 해. 명세와 기술 가이드, 코드 규칙을 확인하고 계획을 세워줘. 코드는 아직 고치지 마." |
| ③ 구현 (Accept edits) | "계획대로 만들어줘. 다 되면 무엇을 만들었는지 쉬운 말로 설명해줘." |
| ④ 확인 | "개발 서버 켜줘." → 브라우저에서 직접 눌러 본다. 고객 화면은 폰 크기로도 본다 |
| ⑤ 커밋 | "자동 검사 돌리고 팀 규칙대로 커밋해줘." |
| ⑥ 푸시·미리보기 | "푸시하고 미리보기 주소 알려줘." |
| ⑦ PR | "이 영역 끝났어. 팀 규칙대로 PR 올려줘." (화면이 바뀌었으면 PR에 스크린샷 첨부) |
| ⑧ 반려됐을 때 | "내 PR에 달린 리뷰를 확인하고 반영해줘." |
| ⑨ 충돌 났을 때 | "main 최신 내용을 내 브랜치에 합치고 충돌을 해결해서 다시 푸시해줘. 다른 사람이 추가한 줄은 지우지 마." |
| ⑩ 머지된 뒤 | "main 받아서 다음 작업 준비해줘." |

다른 사람 담당 기능이 필요할 때:
- "이 작업에 다른 담당자 기능이 필요해. `연결` 라벨 Issue 내용을 정리해줘."
- "DB에 이 필드가 필요해. `schema` 라벨 Issue 내용을 정리해줘."

## 6. 결과 확인하는 방법

| 어디서 | 방법 | 주의 |
| --- | --- | --- |
| 로컬 | "개발 서버 켜줘" → `http://localhost:3000` | 가장 빠르다. 지도와 로그인은 여기서 확인한다 |
| 미리보기 | 브랜치를 푸시하면 Vercel이 그 브랜치만의 주소를 만든다. "내 미리보기 주소 알려줘" | 폰으로 확인하거나 팀원에게 보여줄 때. 로그인은 되고, **카카오 지도는 안 된다** |
| 팀원 작업 | "정찬형 작업 미리보기 보여줘"처럼 이름을 말한다 | 팀원마다 브랜치가 달라서 주소도 다르다. Claude가 그 사람의 PR·브랜치 주소를 찾아 준다 |
| 운영 | `https://toori-ruby.vercel.app` | main에 머지된 결과. 여러 사람 작업이 같이 잘 돌아가는지 본다 |

- 미리보기와 운영 주소 모두 개발용 DB를 같이 쓴다. 테스트 데이터 이름에 자기 이름을 넣는다
- 남의 브랜치를 내 컴퓨터에서 직접 돌려 보고 싶으면 "정찬형 브랜치를 내 컴퓨터에서 실행해줘"라고 한다. Claude가 내 작업을 먼저 안전하게 커밋한 뒤 실행하고, 끝나면 내 브랜치로 돌아온다

로그인 테스트:
- 카카오·구글 간편 로그인만 있다(이메일·비밀번호 로그인 없음, 토스 로그인 없음).
- **구글 로그인은 테스트 사용자로 등록된 팀원 4명의 Gmail만 된다.** 다른 계정은 "액세스 차단"이 뜬다. 새 계정이 필요하면 현동훈에게 요청한다.
- 카카오 로그인은 개인 카카오 계정으로 된다.

| 상황 | 해결 |

| 에러 메시지가 났다 | 에러 전문을 붙여넣고 "원인을 먼저 설명하고 고쳐줘." |
| PR에 충돌이 났다 | 5번 표의 ⑨ 문장 |
| 커밋 전인데 다 되돌리고 싶다 | "마지막 커밋 이후 변경을 모두 버려줘." (복구 불가, 한 번 더 확인) |
| 커밋·푸시한 뒤 되돌리고 싶다 | "방금 커밋을 되돌리는 커밋을 만들어줘(git revert)." |
| 지금 상태가 헷갈린다 | "지금 어느 브랜치에 있고 커밋 안 된 변경이 뭔지 알려줘." |
| 푸시가 거절된다 | "푸시가 왜 거절됐는지 확인하고 해결해줘." (보통 main에 직접 올리려 했거나 최신화가 안 된 경우. main은 GitHub 보호 규칙으로 잠겨 있다) |
| PR에 "Merging is blocked", 머지 버튼이 안 눌린다 | 정상이다. 머지는 현동훈만 한다 |
| 머지된 뒤 GitHub에서 내 브랜치가 사라졌다 | 정상이다(자동 삭제). "main으로 돌아가서 최신화하고 다음 작업 브랜치 만들어줘." |
| Claude가 남의 폴더를 고치려 한다 | 승인하지 말고 "그 파일은 내 담당이 아니야. Issue로 쓸 내용만 정리해줘." |
| `.env.local`이 없다는 에러 | 현동훈에게 파일을 받아 레포 최상위에 둔다 |
| 구글 로그인 "액세스 차단" | 테스트 사용자로 등록 안 된 계정이다. 현동훈에게 요청 |
| 지도가 안 뜬다 | 미리보기 주소라면 로컬(`localhost:3000`)에서 확인한다 |
| `git`·`gh`·`node`를 못 찾는다 | 설치 후 Claude 앱을 완전히 종료했다가 다시 켠다 |
| Claude가 같은 실수를 반복한다 | 새 세션에서 더 구체적으로 다시 시킨다. 팀 전체 문제면 현동훈에게 알려 규칙에 추가 |
| 사용량 한도에 걸렸다 | 초기화 시간까지 기다린다. 다음부터 세션을 짧게, 요청을 구체적으로 |

## 8. 절대 하지 말 것

- main에 직접 커밋·푸시, PR 머지, 강제 푸시(`--force`)
- `.env.local`, API 키, DB 비밀번호를 커밋하거나, 현동훈이 올린 팀 단톡방 외의 곳(다른 단톡방, 노션, Issue·PR, 스크린샷)에 붙이기
- 남의 담당 폴더를 직접 고치기, DB 구조를 직접 바꾸기
- Bypass permissions 모드 쓰기
- 이해하지 못한 코드를 그대로 PR로 올리기 (모르면 "이 코드가 왜 이렇게 동작하는지 설명해줘")
