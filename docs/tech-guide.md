# 기술 가이드

기능 명세([feature-spec.md](feature-spec.md))를 어떤 기술로, 어떤 구조로 만들지와 담당자끼리 맞춰야 할 지점을 정리한 문서다.

- 작업을 시작하기 전에 **2. 공통 원칙**, **자기 담당 섹션**, **4. 연결 지점**을 읽는다.
- **[결정 필요]** 표시는 아직 정해지지 않은 것이다. 임의로 정하지 말고 nnoinn에게 확인한다.
- 이 문서는 nnoinn이 관리한다. 바꿀 내용이 있으면 Issue로 요청한다.

## 1. 기술 스택

| 영역 | 선택 | 상태 | 메모 |
| --- | --- | --- | --- |
| 언어 | TypeScript (strict) | 제안 | 타입이 AI의 실수를 잡아준다 |
| 프레임워크 | Next.js (App Router) | 확정 | 화면과 서버 코드를 한 프로젝트에서 |
| 배포 | Vercel | 확정 | 무료(Hobby)는 비상업용이고 예약 작업이 하루 1회(±59분)로 제한된다. 상용 출시 때 Pro로 전환 |
| DB | Supabase Postgres (서울 리전) + PostGIS | 확정 | PostGIS로 "반경 N km" 검색 |
| DB 도구 | Drizzle ORM + drizzle-kit(마이그레이션) | 확정 | Supabase DB에 접속해서 쓰는 코드용 도구이며 Supabase를 대체하지 않는다. PostGIS 위치 타입을 다루기 쉽다. Vercel에서는 Supabase의 트랜잭션 풀러 주소로 접속하고 prepared statement를 끈다(`prepare: false`) |
| 로그인 | Supabase Auth 간편 로그인: 카카오·구글·네이버 (토스 제외) | 확정 (C-101, S-101) | 줍줍 전용 아이디·비밀번호는 만들지 않는다. 카카오·구글은 Supabase 기본 지원이라 먼저 만들고, 네이버는 Supabase 커스텀 OAuth로 그다음에 만든다(응답 형식 맞추기와 네이버 검수 필요). 토스 로그인은 토스 앱 안의 미니앱(앱인토스) 전용이라 쓰지 않는다 |
| 이미지 저장 | Supabase Storage | 제안 | 샵·스타일 이미지 |
| 결제 | 포트원 V2 (첫 결제사 채널: 토스페이먼츠) | 확정 (X-201) | 우리 코드는 포트원 방식으로만 짜고, 실제 결제사는 포트원 콘솔의 채널로 바꿀 수 있다. 개발은 테스트 채널로 |
| 지도 | 카카오맵 JS SDK + 카카오 로컬 API | 확정 (X-503) | 카카오 로그인과 같은 카카오 개발자 앱에서 관리한다 |
| 알림 | 웹 푸시(PWA) → 앱 푸시(앱 단계) | 확정 | 가장 중요한 건 푸시다. 카카오 알림톡은 사업자 등록 후 구현하고, 문자는 지금은 만들지 않는다(추후 논의) |
| PWA | Next.js manifest + 서비스 워커 | 확정 (웹 퍼스트) | iOS 웹 푸시는 홈 화면에 추가한 경우에만 된다 |
| UI | Tailwind CSS + shadcn/ui | 제안 | 공통 컴포넌트는 `src/components/ui/` |
| 입력 검증 | zod | 제안 | 서버에서 모든 입력을 검증 |
| 테스트 | Vitest(계산·정책), Playwright(화면 흐름) | 제안 | |
| 자동 검사 | ESLint(또는 Biome), 타입 검사, GitHub Actions | 제안 | PR마다 실행 |
| 운영 | Sentry(에러), PostHog(사용자 분석) | 나중 | |

## 2. 공통 원칙

```text
[고객 폰(PWA)]   [업주 PC·태블릿]   [운영자 PC]
 (customer)/        owner/            admin/          ← 화면 (src/app)
        \              |               /
         ▼             ▼              ▼
   서버 (Next.js, Vercel)
   ├─ 화면 전용 서버 코드: 각 화면 폴더 안 (데이터 조회·저장)
   ├─ 공통 로직: src/server/ (결제·환불·정산·알림·정책·권한)
   └─ 외부 입구: src/app/api/ (결제 웹훅 등)
         ▼
   Supabase(DB·로그인·이미지) · 포트원(→ 토스페이먼츠) · 카카오맵/로컬 API · 문자/알림톡
```

- **브라우저는 DB에 직접 접근하지 않는다.** 모든 데이터는 서버를 거친다.
- **권한은 서버에서 검사한다 (X-102).** 서버 함수마다 "로그인했는가, 역할이 맞는가, 본인 데이터인가"를 확인한다. DB 도구(Drizzle·Prisma)는 Supabase RLS를 거치지 않으므로, RLS는 브라우저 직접 접근을 막는 안전장치로만 켠다.
- **금액·시간·상태는 서버가 계산하고, 화면은 표시만 한다.** 브라우저에서 보낸 가격이나 환불액은 믿지 않는다.
- **금액은 원 단위 정수**로 다룬다. **할인가는 원 미만을 버린 뒤 100원 단위로 올린다** (예: 정가 33,500원에 30% 할인 → 23,450원 → 23,500원). 수수료와 정산은 올린 뒤의 금액으로 계산한다. 수수료와 그 VAT는 원 미만만 버린다.
- **시간은 DB에 UTC(timestamptz)로 저장하고, 화면에는 한국 시간으로 표시한다.** 시간 계산은 공용 함수로만 한다.
- **정책 숫자는 `src/server/policy/` 한 곳에 둔다.** 48시간 게시, 위약금 구간(48~24시간 30%, 24~6시간 50%, 6시간 이내 100%), 6시간 임박, 10분 홀딩, 할인율 선택지(10/20/30/40/50%), 할인율별 수수료율(10/9/8/7/6%, 하한 6%), 수수료 VAT 10%, 업주 귀책 보상(고객 할인 쿠폰 3,000원)·패널티(5,000원)가 여기 들어간다. 10.07 회의 확정값이고 법률 확인 후 바뀔 수 있으므로 값만 바꾸면 되게 만든다.
- **매물 상태는 6개 이름만 쓴다:** 예약대기 → 게시중 → 예약됨 / 마감 / 취소 / 완료.
- **시간이 지나면 바뀌는 상태는 예약 작업 없이 계산으로 처리한다.** "게시 시각이 지났으면 게시중", "시작 시각이 지났으면 마감"처럼 조회할 때 현재 시각과 비교한다(X-302, X-303, S-205). Vercel 무료 플랜의 예약 작업 제한을 피하고, 시각도 정확해진다.

## 3. 담당별 가이드

### 3-1. 정찬형 — 고객 화면, 지도

쓰는 기술: Next.js 화면(`src/app/(customer)/`), 카카오맵 JS SDK, 카카오 로컬 API, 브라우저 위치 API, PostGIS 거리 검색, 포트원 결제창 호출(화면 부분)

| 기능 | 만드는 방법 | 주의할 점 |
| --- | --- | --- |
| C-102 위치 권한 | 브라우저 위치 API로 요청, 거부하면 동네 선택 화면 | 위치 API는 HTTPS(또는 localhost)에서만 동작한다 |
| X-501 주소→좌표 | `src/features/map/`에 서버 함수로 만든다. 카카오 로컬 API 호출 | REST 키는 서버에서만 쓴다. **정민석의 매장 등록(S-103)이 이 함수를 쓴다** |
| X-502 지역 분류 | 좌표 변환 결과의 '구' 정보를 샵에 저장 | 필터(C-206)의 지역 기준이 된다 |
| X-503, C-201 지도 | 카카오맵 SDK로 마커 표시, 지도 이동 시 영역 안 매물 조회 | SDK는 브라우저 전용이라 클라이언트 컴포넌트에서만 불러온다. 등록한 도메인에서만 동작하므로 PR 미리보기 주소에서는 안 뜰 수 있다 |
| C-204~206 목록·정렬·필터 | 거리순·필터는 DB에서 계산(PostGIS). 필터 상태는 주소창(쿼리스트링)에 저장 | 전체 매물을 불러와 브라우저에서 정렬하지 않는다. 목록은 나눠서 불러온다 |
| C-203 남은 시간 타이머 | 공통 타이머 컴포넌트 사용 | 사용자 폰의 시계가 틀릴 수 있다. 서버 시각을 기준으로 계산한다 |
| C-306 신규 고객 전용 | 매물 조회 서버 코드에서 강규민의 신규 고객 판별 함수(X-104)로 걸러낸다 | 화면에서 숨기기만 하면 안 된다. 서버에서 빼야 한다 |
| C-305, C-308 환불 규정 노출 | 정책 설정값을 읽어 위약금 3구간(48~24시간 30%, 24~6시간 50%, 6시간 미만 환불 불가)을 안내. 환불 불가 뱃지는 6시간 미만 매물에만 | 문구 안의 숫자도 정책 설정값에서 가져온다. 상세 화면에 "지금 취소하면 N% 환불"은 표시하지 않고, 환불 규정은 결제 동의(C-402)에서 명확하게 보여준다 |
| C-401~406 예약·결제 화면 | 결제창 호출(`PortOne.requestPayment`)과 결과 화면은 정찬형, 주문 생성·홀딩·검증은 강규민 함수 호출. 홀딩 중에는 화면 오른쪽 위에 10분 타이머 | 결제 후 돌아오는 페이지(`redirectUrl`)에서 강규민의 검증 함수를 꼭 호출해야 예약이 확정된다. 타이머는 서버가 준 홀딩 만료 시각으로 계산한다 |
| C-503 예약 취소 | 강규민의 환불 계산 함수 결과를 미리 보여주고, 확인하면 취소 함수 호출 | 환불액을 화면에서 직접 계산하지 않는다 |
| C-101 로그인 화면 | 고객/업주 토글 + 강규민이 설정한 Supabase 간편 로그인 버튼. 고른 값을 강규민의 로그인 함수에 넘긴다 | 로그인 후 돌아올 주소 처리. 업주 계정으로 들어온 상태에서 고객 화면을 열면 예약·결제를 막고 고객 계정으로 다시 들어오라고 안내한다 |
| C-302~304 업주 프로필 보기 | 정민석이 저장한 샵 정보·이미지·서비스 설명을 매물 상세와 함께 표시 | 매물 카드·상세에서 같은 데이터를 쓴다 |
| C-407 쿠폰 적용 (P1) | 결제 화면에서 보유 쿠폰을 고르면 강규민 함수가 계산한 결제 금액을 표시. 결제 1건에 1장 | 금액은 화면에서 계산하지 않는다. 쿠폰을 고르는 곳과 결제 동의(C-402)에 "취소하면 쿠폰은 돌려드리지 않고, 환불은 실제 결제한 금액 기준"이라는 안내를 꼭 넣는다(고객이 위약금을 더 크게 느낄 수 있다). 3단계에 업주 귀책 취소와 함께 만든다(연결 #17) |
| C-601, C-602 푸시 권한·관심 동네 화면 | 권한 요청과 관심 동네 설정 화면은 정찬형, 구독 저장·발송·빈도 제한은 강규민 `notify` | 처음 들어오자마자 묻지 않고 예약 완료 화면에서 처음 묻는다 |

### 3-2. 정민석 — 업주 화면

쓰는 기술: Next.js 화면(`src/app/owner/`), 폼 입력과 zod 검증, 이미지 업로드(Supabase Storage), 타임라인/캘린더 UI, 정찬형의 주소→좌표 함수

| 기능 | 만드는 방법 | 주의할 점 |
| --- | --- | --- |
| S-102 입점 승인 대기 | 샵 상태가 '승인'이 아니면 매물 등록 화면을 막는다 | 화면뿐 아니라 서버에서도 막는다. 승인은 강규민의 운영자 화면(A-101) |
| X-301, X-302 매물 상태 계산 | `src/features/slot-status/`에 순수 함수(저장 상태·게시 시각·시작 시각·현재 시각 → 6개 중 하나)와 목록 조회용 DB 조건을 같이 만든다 | 정찬형 목록, 업주 대시보드, 강규민 결제가 모두 이것을 쓴다. 두 모양이 같은 답을 내는지 같은 테스트로 확인한다 |
| S-103~105 업주 프로필 | 샵 정보(주소 검색 UI → 정찬형의 주소→좌표 함수 → 좌표와 구 저장)·이미지·서비스 설명·외부 링크 | 좌표 변환 실패(없는 주소) 처리. 고객 화면(C-302~304)이 같은 데이터를 보여준다 |
| S-104 이미지 | 서버를 거쳐 Supabase Storage에 업로드 | 용량 제한, 이미지 크기 줄이기 |
| S-106 메뉴·가격표 | 3탭 등록의 전제. 먼저 만든다. 서비스 종류는 업종별 고정 목록에서 고르고, 이름·가격·상세 설명은 업주가 자유롭게 입력 | 정가는 원 단위 정수 |
| S-107 정산 계좌 | 업주 계정 가입 흐름(S-101)에서 사업자 정보와 함께 필수로 받는다. 서버에서 암호화해 저장하고, 업주 화면엔 뒷자리만, 운영자 화면에서만 전체 표시 | 민감 정보. 로그에 남기지 않는다. 나중에 PG 지급대행을 쓰면 이 정보로 업주를 셀러로 등록한다 |
| S-201~204 3탭 매물 등록 | ① 메뉴 ② 시간 ③ 할인율(10/20/30/40/50% 중 선택) → 서버에서 검증 후 저장 | 48시간 이내 시간만 등록 가능(S-204). 선택지에 없는 할인율은 서버에서 거절한다. 화면과 서버 둘 다 검증 |
| S-203 가격 자동 계산 | 할인가·수수료·정산 예정액은 서버(강규민의 정책·정산 함수)가 계산한 값을 표시 | 수수료율은 할인율에 따라 다르다(정책 설정값). 업주에게는 "수수료 N%(VAT 별도), 결제 수수료 별도"를 같이 보여준다 |
| S-206 수정·마감 | 판매 전에만 가능. 삭제 버튼 대신 '마감' 버튼: 사유(다른 곳 예약 / 잘못 올림 / 기타)와 시각을 기록하고 상태를 '마감'으로 바꾼다 | 홀딩 중(결제 진행 중)인 매물은 수정·마감을 막는다. 마감한 매물은 시간 겹침 검사에서 빠지므로 같은 시간에 다시 올릴 수 있다 |
| S-409 업주 귀책 취소 화면 (P1) | 예약된 매물에서 '업주 사정으로 취소' → 확인 창(고객 전액 환불, 고객 쿠폰 3,000원, 패널티 5,000원 안내) → 강규민의 처리 함수 호출(X-207) | 서비스 시작 전까지만 버튼을 보여준다. 금액은 정책 설정값에서 읽는다. 남은 패널티는 정산 내역(S-501)에 표시 |
| S-209 중복 시간대 방지 | DB 제약으로 같은 샵의 시간 겹침을 막는다 (현동훈이 스키마에 넣음) | 버튼을 두 번 눌러 매물이 두 개 생기지 않게 한다 |

### 3-3. 강규민 — 인증·결제·정산·알림·운영자

쓰는 기술: Supabase Auth, 화면 접근 보호(미들웨어), DB 구현(설계는 현동훈), 포트원 V2 브라우저 SDK와 서버 API, 결제 웹훅, 문자/알림톡 서비스, 웹 푸시, Supabase 예약 작업(pg_cron), 운영자 화면(`src/app/admin/`)

| X-101, C-101, S-101 로그인·역할 | Supabase 간편 로그인(카카오·구글 먼저, 네이버 다음) + 사용자 역할(고객/업주/관리자). 첫 로그인 후 약관 동의(C-104), 업주는 업주 입구(`/owner/join`)에서 사업자 정보·정산 계좌(필수) 입력(S-101). **계정 구조:** Supabase 로그인 정보(이메일)는 하나이고, 그 아래 고객 계정과 업주 계정을 별도 레코드로 둔다. 같은 이메일로 둘 다 만들 수 있고 정보·예약·정산은 완전히 따로다. 로그인 화면의 고객/업주 토글 값이 '지금 들어온 계정'이 되고, Custom Access Token Hook으로 토큰에 넣어 `src/proxy.ts`가 `/owner`, `/admin`을 1차로 막는다(서버 함수에서 한 번 더 확인). 업주 계정으로 들어온 상태에서는 예약·결제 함수가 거절한다. 관리자는 nnoinn이 DB에서 지정 | 같은 사람이 다른 간편 로그인으로 들어와도 한 계정이 되도록 각 서비스에서 **이메일 제공 동의**를 받는다(Supabase는 같은 이메일의 로그인을 한 사용자로 묶는다). 카카오에서 이메일을 받으려면 카카오 개발자 콘솔 설정(비즈 앱 전환 등)이 필요할 수 있다 |

| X-104 신규 고객 판별 | `isNewCustomer(userId, shopId)` 같은 서버 함수 | 매물 조회(정찬형)와 결제 직전(재검증) 둘 다에서 쓴다 |
| C-404, X-304 10분 홀딩 | 매물에 '홀딩한 사람'과 '홀딩 만료 시각(지금 + 10분)'을 두고, "게시중이고 홀딩이 없거나 만료된 경우에만" 홀딩하는 업데이트를 한 번에 실행 | 두 명이 동시에 눌러도 한 명만 성공한다. 만료된 홀딩은 시각 비교로 무시하므로 예약 작업이 필요 없다. 홀딩은 상세 화면의 '예약하기'를 누를 때 시작하고, 한 사람당 동시에 1개만. 홀딩 중 매물은 목록에 남기고 "다른 고객이 결제 중"으로 표시할 수 있게 홀딩 여부를 조회 결과에 담는다 |

| X-206, A-105 정산 지급 | MVP는 수기 지급 + 상태 기록. 운영자가 정산 대상을 확인하고 지급 완료를 표시한다 | 고객 돈을 줍줍 계좌로 받아 업주에게 나눠주는 구조는 전자금융거래법상 등록 문제가 생길 수 있다. 출시 때는 PG 지급대행(토스페이먼츠가 업주에게 바로 지급, 업주를 셀러로 등록)을 쓰는 방향으로 검토하므로 지급 부분을 분리해 둔다 |
| S-404, S-400, C-601, C-602 알림 | `notify(이벤트)` 함수 하나로 모으고, 채널은 그 안에서 고른다. 1단계는 웹 푸시(서비스 워커 + VAPID 키, 구독 정보는 DB에 저장), 2단계는 앱 푸시를 같은 함수에 채널로 추가 | 아이폰은 '홈 화면에 추가'한 PWA에서만 웹 푸시를 받는다(iOS 16.4 이상). 사용자가 푸시 권한을 거부하면 알림이 가지 않으니, 권한을 요청하는 시점과 안내 문구가 중요하다. 리마인드(C-602)는 시작 2시간 전과 15분 전에 Supabase 예약 작업(pg_cron)으로 보낸다. 관심 지역 푸시(C-601)는 같은 사람에게 3시간에 최대 1번, 밤 9시~아침 8시에는 보내지 않는다. 웹 푸시는 X-505-1, 앱 푸시는 X-506-2, 알림톡(X-507-3)은 사업자 등록 후, 문자는 보류 |
| A-101~107 운영자 화면 | `src/app/admin/` | 관리자만 접근. 입점 승인 상태는 정민석 화면(S-102)과 연결 |

## 5. 작업 순서

**10/23 개발 시작.** 스프린트(기간 단위)는 두지 않는다. 각자 자기 작업 로드맵(현동훈이 컨펌한 순서)대로 기능을 하나씩 만들어 PR로 올리고, 현동훈은 작업할 때마다 올라온 PR을 처리한다.

아래 단계는 기간이 아니라 **앞뒤 순서**다. 다른 사람의 결과를 기다리지 않도록, 앞 단계의 연결 지점(임시 버전)이 나오면 다음 단계를 시작한다.

1. **뼈대 (Week 0, 현동훈·강규민):** 뼈대, 스키마 v1, 시드 데이터(안산시 미용실·네일샵), 로그인·역할, 공통 UI, 정책 파일 틀, 연결 함수 1~5의 임시 버전
2. **1단계:** 정민석은 샵 프로필·메뉴·3탭 등록, 정찬형은 지도·목록·상세(시드 데이터로), 강규민은 권한·신규 고객 판별·입점 승인·결제 테스트 연동 준비
3. **2단계:** 결제·10분 홀딩·환불(강규민과 정찬형), 방문·노쇼 처리와 정산(정민석과 강규민), 알림
4. **3단계:** P1 기능, 안정화

예전 문서와 Issue의 "Sprint 1·2·3"은 위의 1·2·3단계와 같은 뜻이다.

## 6. 모두가 조심할 문제

| 문제 | 어떻게 터지나 | 막는 방법 |
| --- | --- | --- |
| 시간대 | 서버(UTC)와 한국 시간이 9시간 다르다. 밤 늦게 등록한 매물의 날짜가 하루 밀린다 | 저장은 UTC, 표시는 한국 시간, 계산은 공용 함수로만 |
| 동시성 | 두 사람이 같은 매물을 동시에 결제하거나, 업주가 수정하는 순간 고객이 결제한다 | 결제 잠금, 잠금 중 수정 금지, DB 제약 |
| 권한 | 주소창에 다른 업주의 매물 ID를 넣어 수정 화면에 들어간다 | 서버 함수마다 소유자 확인 |
| 금액 조작 | 브라우저에서 할인가를 바꿔 결제를 요청한다 | 금액은 서버가 계산하고, 결제 승인 때 금액을 검증 |
| 비밀 키 노출 | `NEXT_PUBLIC_`으로 시작하는 환경변수는 브라우저에 그대로 보인다 | 비밀 키에는 이 접두어를 붙이지 않는다. `.env`는 커밋하지 않는다 |
| 테스트·실제 키 혼동 | 테스트 키로 실제 결제를 시도하거나 그 반대 | 개발·미리보기는 테스트 키만 쓴다 |
| 개인정보 | 연락처나 계좌번호가 로그나 다른 업주 화면에 노출된다 | 필요한 사람에게만 보이고, 로그에 남기지 않는다 |
| 미리보기 주소 | PR마다 미리보기 주소가 달라서 지도, 로그인 복귀, 결제 복귀가 막힌다 | 현동훈이 Week 0에 외부 서비스 도메인을 설정하고 확인 |
| 무료 플랜 제한 | Supabase 무료 프로젝트는 1주일 동안 안 쓰면 일시 정지된다. Vercel 무료는 예약 작업이 하루 1회 | 시간 기반 상태는 계산으로 처리, 정확한 예약 발송은 pg_cron |
| 이미지 | 큰 사진 때문에 목록이 느려진다 | 업로드할 때 크기를 줄이고, 목록엔 작은 이미지 |
| package.json 충돌 | 여러 명이 동시에 패키지를 설치한다 | 설치 전에 묻고, PR에 이유를 적는다 |

## 8. 개발과 확인 환경

코드를 고치면서 결과를 확인하는 곳은 세 군데다.

| 환경 | 주소 | 언제 쓰나 | 연결되는 것 |
| --- | --- | --- | --- |
| 로컬 | `http://localhost:3000` | 코드를 고치면서 바로 확인 (가장 빠름) | 개발용 Supabase, 포트원 테스트 채널 |
| 미리보기 | 브랜치에 푸시할 때마다 Vercel이 만드는 주소 | 폰에서 확인, PR 리뷰 | 개발용 Supabase, 포트원 테스트 채널 |
| 운영 | main 배포 주소 (나중에 도메인 연결) | 실제 서비스 | 운영용 Supabase, 출시 후 실제 결제 채널 |

- **Vercel 프로젝트는 nnoinn 계정이 소유한다.** Vercel 문서상, 무료(Hobby) 플랜의 "커밋 작성자 = 소유자" 제한은 GitHub 조직 레포에만 적용되고 개인 계정 레포의 협업자에게는 적용되지 않는다. 그래서 팀원 커밋도 배포된다. **레포를 GitHub 조직으로 옮기면 무료 플랜으로는 배포할 수 없으니, 옮기기 전에 Pro로 전환한다.**
- **미리보기 주소는 PR에 Vercel 봇 코멘트로 달린다.** 푸시한 뒤 사용자가 원하면 Claude가 GitHub의 배포 상태에서 그 커밋의 미리보기 주소를 찾아 알려준다. 확인하고 싶을 때는 하루 끝이 아니어도 자기 브랜치에 언제든 푸시해도 된다.
- **미리보기 보호(Vercel Authentication)는 nnoinn이 꺼 둔다.** 켜져 있으면 Vercel 계정이 없는 팀원은 미리보기를 볼 수 없다. 미리보기에는 테스트 데이터와 테스트 결제만 쓴다.
- **Supabase는 개발용·운영용 프로젝트를 따로 둔다.** 로컬과 미리보기는 개발용을 쓴다. 개발 DB는 4명이 같이 쓰므로 남이 만든 데이터를 지우지 않는다. 테이블 구조는 nnoinn이 승인한 마이그레이션으로만 바꾼다.
- **환경변수:** 로컬은 각자 `.env.local`(nnoinn이 팀원 4명만 있는 단톡방으로 전달, 개발용 키만), Vercel 환경변수는 nnoinn이 관리한다. 운영용 키는 단톡방으로 보내지 않는다. 포트원 API 시크릿, Supabase 서비스 키 같은 비밀 값은 `NEXT_PUBLIC_`을 붙이지 않는다.
- **외부 서비스의 도메인 등록:** 카카오 지도 SDK와 로그인 복귀 주소는 등록한 도메인에서만 동작한다. 미리보기 주소는 브랜치마다 달라서 지도·로그인이 안 될 수 있으니, 그런 기능은 로컬에서 먼저 확인한다. 도메인 설정은 nnoinn이 Week 0에 한다.

### 외부 서비스 계정 현황 (2026-10-11 기준)

모든 서비스는 지금 nnoinn(현동훈) 개인 계정으로 만들어져 있고, 사업화할 때 줍줍 계정으로 한 번에 옮긴다. 팀원은 관리 화면에 로그인할 필요 없이 `.env.local`의 키로 개발한다. 관리 화면이 꼭 필요하면 nnoinn이 그 사람의 개인 계정을 멤버로 초대한다(비밀번호 공유 금지).

### 환경변수

변수 이름은 레포의 `.env.example`에 있다. 값은 `.env.local`에만 넣는다.

| 변수 | 공개 여부 | 쓰는 곳 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | 브라우저에 보여도 됨 | Supabase 접속 주소 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 브라우저에 보여도 됨 | 로그인 등 Supabase 클라이언트 |
| `SUPABASE_SECRET_KEY` | **서버 전용** | 관리자 권한 작업(시드 데이터 등) |
| `DATABASE_URL` | **서버 전용** | Drizzle DB 접속 (트랜잭션 풀러, 포트 6543) |
| `NEXT_PUBLIC_KAKAO_MAP_JS_KEY` | 브라우저에 보여도 됨 (등록한 도메인에서만 동작) | 카카오 지도 표시 |
| `KAKAO_REST_API_KEY` | **서버 전용** | 주소→좌표 변환(카카오 로컬 API) |

카카오·구글 로그인의 Client ID·Secret은 Supabase 대시보드에 들어 있어서 우리 코드에는 없다. 새 환경변수가 필요하면 `.env.example`에 이름을 추가하는 PR을 올리고, 값은 nnoinn에게 받는다.
