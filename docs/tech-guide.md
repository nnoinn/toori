# 기술 가이드

기능 명세([feature-spec.md](feature-spec.md))를 어떤 기술로, 어떤 구조로 만들지와 담당자끼리 맞춰야 할 지점을 정리한 문서다.

- 작업을 시작하기 전에 **2. 공통 원칙**, **자기 담당 섹션**, **4. 연결 지점**을 읽는다.
- **[결정 필요]** 표시는 아직 정해지지 않은 것이다. 임의로 정하지 말고 nnoinn에게 확인한다.
- 이 문서는 nnoinn이 관리한다. 바꿀 내용이 있으면 Issue로 요청한다.

## 1. 기술 스택

| 영역 | 선택 | 상태 | 메모 |
| --- | --- | --- | --- |
| 언어 | TypeScript 5 (strict) | 확정 | 타입이 AI의 실수를 잡아준다 |
| 프레임워크 | Next.js 16.4 (App Router, Turbopack) + React 19 | 확정 | 화면과 서버 코드를 한 프로젝트에서. **Cache Components가 켜져 있다**: 데이터 읽기는 기본으로 요청 때마다 하고, 캐시는 `use cache`로 고른다. 쿠키·세션을 읽는 화면은 `<Suspense>` 안에 둔다. 화면 접근 보호는 `src/proxy.ts`(예전 이름 middleware). 이 버전은 학습 내용과 다를 수 있으니 `node_modules/next/dist/docs/`를 먼저 읽는다(특히 `01-app/02-guides/authentication-with-cache-components.md`) |

| 배포 | Vercel | 확정 | 무료(Hobby)는 비상업용이고 예약 작업이 하루 1회(±59분)로 제한된다. 상용 출시 때 Pro로 전환 |

| 이미지 저장 | Supabase Storage | 확정 | 샵·스타일 이미지. `next.config.ts`에서 `*.supabase.co`의 공개 버킷 이미지를 `next/image`로 쓸 수 있게 해 두었다 |
| 결제 | 포트원 V2 (첫 결제사 채널: 토스페이먼츠) | 확정 (X-201) | 우리 코드는 포트원 방식으로만 짜고, 실제 결제사는 포트원 콘솔의 채널로 바꿀 수 있다. 개발은 테스트 채널로 |
| 지도 | 카카오맵 JS SDK + 카카오 로컬 API | 확정 (X-503) | 카카오 로그인과 같은 카카오 개발자 앱에서 관리한다 |
| 알림 | 웹 푸시(PWA) → 앱 푸시(앱 단계) | 확정 | 가장 중요한 건 푸시다. 카카오 알림톡은 사업자 등록 후 구현하고, 문자는 지금은 만들지 않는다(추후 논의) |

## 2. 공통 원칙

```text
[고객 폰(PWA)]   [원장님 PC·태블릿]   [운영자 PC]
 (customer)/        owner/            admin/          ← 화면 (src/app)
        \              |               /
         ▼             ▼              ▼
   서버 (Next.js, Vercel)
   ├─ 화면 전용 서버 코드: 각 화면 폴더 안 (데이터 조회·저장)
   ├─ 공통 로직: src/server/ (결제·환불·정산·알림·정책·권한)
   └─ 외부 입구: src/app/api/ (결제 웹훅 등)
         ▼
   Supabase(DB·로그인·이미지) · 포트원(→ 토스페이먼츠) · 카카오맵/로컬 API · 문자/알림톡
```

- **브라우저는 DB에 직접 접근하지 않는다.** 모든 데이터는 서버를 거친다.
- **권한은 서버에서 검사한다 (X-102).** 서버 함수마다 "로그인했는가, 역할이 맞는가, 본인 데이터인가"를 확인한다. DB 도구(Drizzle·Prisma)는 Supabase RLS를 거치지 않으므로, RLS는 브라우저 직접 접근을 막는 안전장치로만 켠다.
- **금액·시간·상태는 서버가 계산하고, 화면은 표시만 한다.** 브라우저에서 보낸 가격이나 환불액은 믿지 않는다.
- **금액은 원 단위 정수**로 다룬다. **할인가는 정가 × (1 − 할인율)을 그대로 쓰고 100원 단위로 올리지 않는다** (예: 정가 33,500원에 30% 할인 → 23,450원). 표시한 할인율과 실제 할인율이 같아야 하기 때문이다. 원 미만이 생기면 버린다. 수수료와 정산은 이 금액으로 계산한다. 수수료와 그 VAT는 원 미만만 버린다.
- **시간은 DB에 UTC(timestamptz)로 저장하고, 화면에는 한국 시간으로 표시한다.** 시간 계산은 공용 함수로만 한다.
- **정책 숫자는 `src/server/policy/` 한 곳에 둔다.** 48시간 게시, 위약금 구간(48~24시간 30%, 24~6시간 50%, 6시간 이내 100%), 6시간 임박, 10분 홀딩, 할인율 선택지(10/20/30/40/50%), 할인율별 수수료율(10/9/8/7/6%, 하한 6%), 수수료 VAT 10%, 원장님 귀책 보상(고객 할인 쿠폰 3,000원)·패널티(5,000원)가 여기 들어간다. 10.07 회의 확정값이고 법률 확인 후 바뀔 수 있으므로 값만 바꾸면 되게 만든다.
- **매물 상태는 6개 이름만 쓴다:** 예약대기 → 게시중 → 예약됨 / 마감 / 취소 / 완료.
- **시간이 지나면 바뀌는 상태는 예약 작업 없이 계산으로 처리한다.** "게시 시각이 지났으면 게시중", "시작 시각이 지났으면 마감"처럼 조회할 때 현재 시각과 비교한다(X-302, X-303, S-205). Vercel 무료 플랜의 예약 작업 제한을 피하고, 시각도 정확해진다.

## 3. 담당별 가이드

### 3-1. 정찬형 — 고객 화면, 지도

쓰는 기술: Next.js 화면(`src/app/(customer)/`), 카카오맵 JS SDK, 카카오 로컬 API, 브라우저 위치 API, PostGIS 거리 검색, 포트원 결제창 호출(화면 부분)

| 기능 | 만드는 방법 | 주의할 점 |
| --- | --- | --- |
| C-102 위치 권한 | 브라우저 위치 API로 요청, 거부하면 동네 선택 화면 | 위치 API는 HTTPS(또는 localhost)에서만 동작한다. 위치를 쓸 때마다 서버가 `location_use_logs`에 이용 사실만 남긴다(좌표는 저장하지 않음, 위치정보법) |
| X-501 주소→좌표 | `src/features/map/`에 서버 함수로 만든다. 카카오 로컬 API 호출 | REST 키는 서버에서만 쓴다. **정민석의 매장 등록(S-103)이 이 함수를 쓴다** |
| X-502 지역 분류 | 좌표 변환 결과의 '구' 정보를 샵에 저장 | 필터(C-206)의 지역 기준이 된다 |
| X-503, C-201 지도 | 카카오맵 SDK로 마커 표시, 지도 이동 시 영역 안 매물 조회 | SDK는 브라우저 전용이라 클라이언트 컴포넌트에서만 불러온다. 등록한 도메인에서만 동작하므로 PR 미리보기 주소에서는 안 뜰 수 있다 |
| C-204~206 목록·정렬·필터 | 거리순·필터는 DB에서 계산(PostGIS). 필터 상태는 주소창(쿼리스트링)에 저장 | 전체 매물을 불러와 브라우저에서 정렬하지 않는다. 목록은 나눠서 불러온다 |
| C-203 남은 시간 타이머 | 공통 타이머 컴포넌트 사용 | 사용자 폰의 시계가 틀릴 수 있다. 서버 시각을 기준으로 계산한다 |
| C-306 신규 고객 전용 | 매물 조회 서버 코드에서 강규민의 신규 고객 판별 함수(X-104)로 걸러낸다 | 화면에서 숨기기만 하면 안 된다. 서버에서 빼야 한다 |
| C-305, C-308 환불 규정 노출 | 정책 설정값을 읽어 위약금 3구간(48~24시간 30%, 24~6시간 50%, 6시간 미만 환불 불가)을 안내. 환불 불가 뱃지는 6시간 미만 매물에만 | 문구 안의 숫자도 정책 설정값에서 가져온다. 상세 화면에 "지금 취소하면 N% 환불"은 표시하지 않고, 환불 규정은 결제 동의(C-402)에서 명확하게 보여준다 |
| C-401~406 예약·결제 화면 | 결제창 호출(`PortOne.requestPayment`)과 결과 화면은 정찬형, 주문 생성·홀딩·검증은 강규민 함수 호출. 홀딩 중에는 화면 오른쪽 위에 10분 타이머 | 결제 후 돌아오는 페이지(`redirectUrl`)에서 강규민의 검증 함수를 꼭 호출해야 예약이 확정된다. 타이머는 서버가 준 홀딩 만료 시각으로 계산한다 |
| C-503 예약 취소 | 강규민의 환불 계산 함수 결과를 미리 보여주고, 확인하면 취소 함수 호출 | 환불액을 화면에서 직접 계산하지 않는다 |
| C-101 로그인 화면 | 고객/원장님 토글 + 강규민이 설정한 Supabase 간편 로그인 버튼. 고른 값을 강규민의 로그인 함수에 넘긴다 | 로그인 후 돌아올 주소 처리. 원장님 계정으로 들어온 상태에서 고객 화면을 열면 예약·결제를 막고 고객 계정으로 다시 들어오라고 안내한다 |
| C-302~304 원장님 프로필 보기 | 정민석이 저장한 샵 정보·이미지·서비스 설명을 매물 상세와 함께 표시 | 매물 카드·상세에서 같은 데이터를 쓴다 |
| C-407 쿠폰 적용 (P1) | 결제 화면에서 보유 쿠폰을 고르면 강규민 함수가 계산한 결제 금액을 표시. 결제 1건에 1장 | 금액은 화면에서 계산하지 않는다. 쿠폰을 고르는 곳과 결제 동의(C-402)에 "취소하면 쿠폰은 돌려드리지 않고, 환불은 실제 결제한 금액 기준"이라는 안내를 꼭 넣는다(고객이 위약금을 더 크게 느낄 수 있다). 3단계에 원장님 귀책 취소와 함께 만든다(연결 #17) |
| C-601, C-602 푸시 권한·관심 동네 화면 | 권한 요청과 관심 동네 설정 화면은 정찬형, 구독 저장·발송·빈도 제한은 강규민 `notify` | 처음 들어오자마자 묻지 않고 예약 완료 화면에서 처음 묻는다 |

### 3-2. 정민석 — 원장님 화면

쓰는 기술: Next.js 화면(`src/app/owner/`), 폼 입력과 zod 검증, 이미지 업로드(Supabase Storage), 타임라인/캘린더 UI, 정찬형의 주소→좌표 함수

| 기능 | 만드는 방법 | 주의할 점 |
| --- | --- | --- |
| S-102 입점 승인 대기 | 샵 상태가 '승인'이 아니면 매물 등록 화면을 막는다 | 화면뿐 아니라 서버에서도 막는다. 승인은 강규민의 운영자 화면(A-101) |
| X-301, X-302 매물 상태 계산 | `src/features/slot-status/`에 순수 함수(저장 상태·게시 시각·시작 시각·현재 시각 → 6개 중 하나)와 목록 조회용 DB 조건을 같이 만든다 | 정찬형 목록, 원장님 대시보드, 강규민 결제가 모두 이것을 쓴다. 두 모양이 같은 답을 내는지 같은 테스트로 확인한다 |
| S-103~105 원장님 프로필 | 샵 정보(주소 검색 UI → 정찬형의 주소→좌표 함수 → 좌표와 구 저장)·이미지·서비스 설명·외부 링크 | 좌표 변환 실패(없는 주소) 처리. 고객 화면(C-302~304)이 같은 데이터를 보여준다 |
| S-104 이미지 | 서버를 거쳐 Supabase Storage에 업로드 | 용량 제한, 이미지 크기 줄이기 |
| S-106 메뉴·가격표 | 3탭 등록의 전제. 먼저 만든다. 서비스 종류는 업종별 고정 목록에서 고르고, 이름·가격·상세 설명은 원장님이 자유롭게 입력 | 정가는 원 단위 정수 |

## 5. 작업 순서

**10/23 개발 시작.** 스프린트(기간 단위)는 두지 않는다. 각자 자기 작업 로드맵(현동훈이 컨펌한 순서)대로 기능을 하나씩 만들어 PR로 올리고, 현동훈은 작업할 때마다 올라온 PR을 처리한다.

아래 단계는 기간이 아니라 **앞뒤 순서**다. 다른 사람의 결과를 기다리지 않도록, 앞 단계의 연결 지점(임시 버전)이 나오면 다음 단계를 시작한다.

1. **뼈대 (Week 0, 현동훈·강규민):** 뼈대, 스키마 v1, 시드 데이터(안산시 미용실·네일샵), 로그인·역할, 공통 UI, 정책 파일 틀, 연결 함수 1~5의 임시 버전
2. **1단계:** 정민석은 샵 프로필·메뉴·3탭 등록, 정찬형은 지도·목록·상세(시드 데이터로), 강규민은 권한·신규 고객 판별·입점 승인·결제 테스트 연동 준비
3. **2단계:** 결제·10분 홀딩·환불(강규민과 정찬형), 방문·노쇼 처리와 정산(정민석과 강규민), 알림
4. **3단계:** P1 기능, 안정화

예전 문서와 Issue의 "Sprint 1·2·3"은 위의 1·2·3단계와 같은 뜻이다.

## 6. 모두가 조심할 문제

| 문제 | 어떻게 터지나 | 막는 방법 |
| --- | --- | --- |
| 시간대 | 서버(UTC)와 한국 시간이 9시간 다르다. 밤 늦게 등록한 매물의 날짜가 하루 밀린다 | 저장은 UTC, 표시는 한국 시간, 계산은 공용 함수로만 |
| 동시성 | 두 사람이 같은 매물을 동시에 결제하거나, 원장님이 수정하는 순간 고객이 결제한다 | 결제 잠금, 잠금 중 수정 금지, DB 제약 |
| 권한 | 주소창에 다른 원장님의 매물 ID를 넣어 수정 화면에 들어간다 | 서버 함수마다 소유자 확인 |
| 금액 조작 | 브라우저에서 할인가를 바꿔 결제를 요청한다 | 금액은 서버가 계산하고, 결제 승인 때 금액을 검증 |
| 비밀 키 노출 | `NEXT_PUBLIC_`으로 시작하는 환경변수는 브라우저에 그대로 보인다 | 비밀 키에는 이 접두어를 붙이지 않는다. `.env`는 커밋하지 않는다 |
| 테스트·실제 키 혼동 | 테스트 키로 실제 결제를 시도하거나 그 반대 | 개발·미리보기는 테스트 키만 쓴다 |
| 개인정보 | 연락처나 계좌번호가 로그나 다른 원장님 화면에 노출된다 | 필요한 사람에게만 보이고, 로그에 남기지 않는다 |
| 미리보기 주소 | PR마다 미리보기 주소가 달라서 지도, 로그인 복귀, 결제 복귀가 막힌다 | 현동훈이 Week 0에 외부 서비스 도메인을 설정하고 확인 |
| 무료 플랜 제한 | Supabase 무료 프로젝트는 1주일 동안 안 쓰면 일시 정지된다. Vercel 무료는 예약 작업이 하루 1회 | 시간 기반 상태는 계산으로 처리, 정확한 예약 발송은 pg_cron |
| 이미지 | 큰 사진 때문에 목록이 느려진다 | 업로드할 때 크기를 줄이고, 목록엔 작은 이미지 |
| package.json 충돌 | 여러 명이 동시에 패키지를 설치한다 | 설치 전에 묻고, PR에 이유를 적는다 |

## 8. 개발과 확인 환경

코드를 고치면서 결과를 확인하는 곳은 세 군데다.

| 환경 | 주소 | 언제 쓰나 | 연결되는 것 |
| --- | --- | --- | --- |
| 로컬 | `http://localhost:3000` | 코드를 고치면서 바로 확인 (가장 빠름) | 개발용 Supabase, 포트원 테스트 채널 |
| 미리보기 | 브랜치에 푸시할 때마다 Vercel이 만드는 주소 | 폰에서 확인, PR 리뷰 | 개발용 Supabase, 포트원 테스트 채널 |
| 운영 | main 배포 주소 (나중에 도메인 연결) | 실제 서비스 | 운영용 Supabase, 출시 후 실제 결제 채널 |

- **Vercel 프로젝트는 nnoinn 계정(무료 Hobby)이 소유하고, 레포는 공개다(10/13).** 무료 플랜은 비공개 레포에서 소유자 커밋만 배포한다(10/13 정찬형 테스트에서 "Git author must have access" 로 막힘). 그래서 레포를 공개로 바꿨고, 공개 레포는 팀원 커밋도 배포된다. **출시 전에 Pro로 바꾼다**(무료 플랜은 비상업용). Pro로 바꾸면 레포를 다시 비공개로 돌릴 수 있다
- **레포가 공개라서 누구나 코드·문서·Issue·PR을 볼 수 있다.** Issue·PR·커밋 메시지·코드에 이메일, 전화번호, 계좌번호, API 키를 쓰지 않는다. 테스트 계정 이메일처럼 필요한 개인정보는 단톡방으로 주고받고 nnoinn이 따로 관리한다. 커밋 이메일은 GitHub noreply 주소를 쓴다(온보딩 2-3). 라이선스 파일을 두지 않아서 공개돼도 다른 사람이 코드를 가져다 쓸 권리는 없다
- **미리보기 주소(팀원마다 다른 주소):** 브랜치를 푸시하면 Vercel이 그 브랜치만의 미리보기를 만든다. 팀원마다 작업 브랜치가 다르니 주소도 서로 다르다.
  - **브랜치 고정 주소:** `https://toori-git-<브랜치>-nnoinns-projects.vercel.app`(브랜치 이름의 `/`는 `-`). 예: `feat/owner-slot-register` → `toori-git-feat-owner-slot-register-nnoinns-projects.vercel.app`. 같은 브랜치에 다시 푸시하면 같은 주소가 최신 내용으로 바뀐다. 브랜치 이름이 30자를 넘으면 Vercel이 주소를 줄여 이 공식이 안 맞을 수 있으니 브랜치 이름은 짧게 짓는다
  - **주소 찾는 법(Claude가 한다):** ① PR이 있으면 PR의 Vercel 봇 코멘트(빌드가 끝나면 주소가 생긴다) ② PR이 없으면 위 공식으로 주소를 만들고 `curl -s -o /dev/null -w "%{http_code}" <주소>`로 200인지 본다. 페이지 제목이 "Deployment is building"이면 빌드 중이니 1~2분 뒤 다시 본다 ③ 404면 아직 푸시하지 않았거나 주소가 줄어든 것이니 `gh api "repos/nnoinn/toori/deployments?ref=<브랜치>"`의 배포 상태에서 `environment_url`을 찾는다 ④ 배포가 아예 없거나 Vercel이 "배포가 막혔다"는 코멘트를 달면 nnoinn에게 알린다
  - **다른 팀원 작업 보기:** "정찬형 작업 미리보기 보여줘"라고 하면 Claude가 그 사람의 열린 PR(`gh pr list --author <GitHub 아이디>`)과 최근 푸시한 브랜치를 찾아 미리보기 주소를 알려준다. GitHub 아이디: 정찬형 `chosanai`, 정민석 `alstjr62`, 강규민 `poiuyst282-ui`, 현동훈 `nnoinn`
  - **합쳐진 결과:** main에 머지된 것은 운영 주소 `https://toori-ruby.vercel.app`에서 본다. 여러 사람 작업이 같이 잘 돌아가는지는 여기서 확인한다
  - **미리보기도 개발용 DB를 같이 쓴다.** 미리보기에서 만든 테스트 데이터는 모두에게 보이니 이름에 자기 이름을 넣는다
  - 확인하고 싶을 때는 하루 끝이 아니어도 자기 브랜치에 언제든 푸시해도 된다
- **미리보기에서 되는 것과 안 되는 것:** 로그인은 된다(Supabase 복귀 주소에 미리보기 주소 전체를 등록함). **카카오 지도는 안 된다.** 카카오는 주소를 하나씩 등록해야 해서 로컬(`http://localhost:3000`)과 운영 주소만 등록했다. 지도는 로컬이나 머지 후 운영 주소에서 확인한다
- **남의 브랜치를 내 컴퓨터에서 실행할 때(필요할 때만):** Claude는 먼저 내 작업을 커밋(필요하면 푸시)해 안전하게 둔 뒤, 그 브랜치를 받아 `npm install` → `npm run dev`로 실행하고, 끝나면 내 브랜치로 돌아온다. 로그인 복귀 주소가 `http://localhost:3000`만 등록돼 있으니 포트 3000으로 실행한다. 남의 브랜치에서는 커밋·푸시하지 않는다
- **미리보기 보호(Vercel Authentication)는 nnoinn이 꺼 둔다.** 켜져 있으면 Vercel 계정이 없는 팀원은 미리보기를 볼 수 없다. 미리보기에는 테스트 데이터와 테스트 결제만 쓴다.
- **Supabase는 개발용·운영용 프로젝트를 따로 둔다.** 로컬과 미리보기는 개발용을 쓴다. 개발 DB는 4명이 같이 쓰므로 남이 만든 데이터를 지우지 않는다. 테이블 구조는 nnoinn이 승인한 마이그레이션으로만 바꾼다.
- **환경변수:** 로컬은 각자 `.env.local`(nnoinn이 팀원 4명만 있는 단톡방으로 전달, 개발용 키만), Vercel 환경변수는 nnoinn이 관리한다. 운영용 키는 단톡방으로 보내지 않는다. 포트원 API 시크릿, Supabase 서비스 키 같은 비밀 값은 `NEXT_PUBLIC_`을 붙이지 않는다.
- **외부 서비스의 도메인 등록(10/13 완료):** Supabase 로그인 복귀 주소에 `http://localhost:3000/**`, `https://toori-ruby.vercel.app/**`, `https://toori-*-nnoinns-projects.vercel.app/**`(모든 미리보기). 카카오 JavaScript SDK 도메인에 `http://localhost:3000`, `https://toori-ruby.vercel.app`. 새 주소(도메인 구매 등)가 생기면 nnoinn이 두 곳에 추가한다

### 환경변수

변수 이름은 레포의 `.env.example`에 있다. 값은 `.env.local`에만 넣는다.

| 변수 | 공개 여부 | 쓰는 곳 |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | 브라우저에 보여도 됨 | Supabase 접속 주소 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 브라우저에 보여도 됨 | 로그인 등 Supabase 클라이언트 |
| `SUPABASE_SECRET_KEY` | **서버 전용** | 관리자 권한 작업(시드 데이터 등) |
| `DATABASE_URL` | **서버 전용** | Drizzle DB 접속 (트랜잭션 풀러, 포트 6543) |
| `NEXT_PUBLIC_KAKAO_MAP_JS_KEY` | 브라우저에 보여도 됨 (등록한 도메인에서만 동작) | 카카오 지도 표시 |
| `KAKAO_REST_API_KEY` | **서버 전용** | 주소→좌표 변환(카카오 로컬 API) |

카카오·구글 로그인의 Client ID·Secret은 Supabase 대시보드에 들어 있어서 우리 코드에는 없다. 새 환경변수가 필요하면 `.env.example`에 이름을 추가하는 PR을 올리고, 값은 nnoinn에게 받는다.
