# 팀 공지

nnoinn이 팀원에게 알릴 내용을 PR과 함께 이 파일에 추가한다. **새 공지는 맨 위에** 쓴다.
팀원의 Claude는 세션을 시작할 때 새로 추가된 공지를 자동으로 읽고 요약해서 알려준다(`scripts/session-start.mjs`).

형식:

```text
## YYYY-MM-DD · 대상(전원 또는 이름)
- 무엇이 바뀌었나
- 할 일: 팀원이 해야 할 것 (없으면 "없음")
```

## 2026-10-12 · 전원 (서비스 이름 '투리', 용어 통일)
- **서비스 이름이 '투리'(toori)로 바뀌었다.** 레포 이름도 `nnoinn/toori`로 바뀌었다. 예전 주소(`nnoinn/jupjup`)는 GitHub가 새 주소로 넘겨줘서 푸시·풀은 그대로 된다. 각자 컴퓨터의 `jupjup` 폴더 이름은 바꾸지 않는다(바꾸면 Claude Code 세션 기록이 새로 시작된다)
- **용어:** 판매 단위는 "매물", 매장 주인은 "원장님"이다. 화면뿐 아니라 문서에서도 '업주' 대신 '원장님'이라고 쓴다. 코드 이름(`owner`, `slot`)은 그대로다
- 화면에 서비스 이름을 직접 쓰지 않고 `src/lib/site.ts`의 `SITE_NAME`을 쓴다(이미 '투리'로 바뀌었다)
- 할 일: Claude에게 "레포 주소를 nnoinn/toori로 바꿔줘"라고 한다. 자기 로드맵 Issue의 '줍줍'·'업주'도 새 말로 고친다

## 2026-10-12 · 전원 (할인가 계산)
- **할인가를 100원 단위로 올리지 않는다.** 할인가 = 정가 × (1 − 할인율) 그대로다(정가 33,500원, 30% 할인 → 23,450원). 올리면 실제 할인율이 화면에 표시한 할인율보다 작아져서 할인 표시에 법적인 문제가 생길 수 있다. 원 미만이 생기면 버린다
- 10/11 공지의 "100원 단위 올림"은 없어졌다
- 할 일: 강규민은 정책 함수(W4)에, 정민석은 가격 미리보기(S-203)에 반영한다. 나머지는 없음

## 2026-10-12 · 전원 (Issue 닫기, 쿠폰 거래 정산)
- **Issue 닫기:** 자기가 올린 Issue는 자기가 확인하고 닫는다. 요청·질문이 하나라도 남아 있으면 닫지 않는다. 세션 브리핑에 "내가 올린 열린 Issue"가 나오니, 답이 달렸으면 Claude에게 "내 Issue 답 확인하고 닫아도 되는지 봐줘"라고 한다
- PR 설명의 `Closes #번호`는 그 PR로 Issue가 완전히 해결될 때만 쓴다(머지되면 Issue가 자동으로 닫힌다). 일부만 해결하면 `Refs #번호`
- **쿠폰 거래 정산이 바뀌었다:** 쿠폰은 "줍줍이 고객 대신 낸 돈"으로 보고, 플랫폼 수수료·결제 수수료·업주 정산은 쿠폰과 상관없이 판매가 기준으로 계산한다. 업주에게 받는 결제 수수료는 "판매가의 N%"다. 쿠폰 비용과 쿠폰으로 줄어든 PG 비용은 줍줍 몫에서 정리된다. 계산 예시는 노션 CORE '서비스 규정에 관한 내용'의 "쿠폰 결제의 수수료·정산"
- 할 일: 강규민은 정산 계산(W8) 설계에 반영한다. 나머지는 없음

## 2026-10-11 · 전원 (계정·쿠폰 결정, 명세 동기화)
- **계정 방식이 바뀌었다(앞의 Issue 답보다 이 공지가 우선):** 로그인 화면에서 고객/업주를 토글로 고르고, 같은 이메일로 고객 계정과 업주 계정을 따로 만들 수 있다. 두 계정의 정보·예약·정산은 완전히 따로이고, 업주 계정으로는 예약·결제를 할 수 없다. 로그인 정보는 하나, 계정은 둘인 구조다(CLAUDE.md 핵심 비즈니스 규칙)
